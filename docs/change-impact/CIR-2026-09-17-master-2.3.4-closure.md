# CIR — MASTER 2.3.4 FUNCTIONAL CLOSURE

Date: 2026-09-17
Risk: HIGH (cross-domain product closure; financial/auth/offline surfaces included)
Production mutation at this stage: NONE

## Change intent

Replace the misleading notion that catalogue presence equals implementation with a measurable Master 2.3.4 readiness model, then progressively close the missing operational journeys without destroying acquired 1.3.4 behaviour.

## Canonical owners and dependencies

- Membership/identity lifecycle: Domain + Completion + Group Pairing + Identity Proof.
- Rubrics and living rules: Rubrics service; ledger effects delegated to the canonical financial services.
- Meetings: MeetingService + Completion + canonical ledger/obligations.
- Finance: LedgerService, Receivables/Treasury/Risk, Completion loan workflow; no workspace-based financial truth.
- Communication/community: Community + Community Realtime; external channel adapters remain provider-gated.
- Discovery/recruitment: Discovery + Membership Gateway; privacy/anti-enumeration preserved.
- Non-financial operational dossiers: Universal Workspace may persist governed records, but cannot become a second ledger, loan book, membership authority or inventory authority.
- Marketplace: Market service and canonical stock/order records.
- Ads: AdManager.
- Documents: Group Documents + R2/import pipeline.
- Offline: Outbox/relay; no false success.
- Platform truth: Feature Registry + Module Registry + Project Truth Ledger.

## Changes allowed in the closure

1. Add a machine-readable readiness/completeness model with evidence and blockers.
2. Upgrade operational UI for still-structural Master capabilities, prioritising member lifecycle, meeting governance, obligations/recovery, reporting/exports, Discovery/recruitment and notifications.
3. Add/reuse API contracts and domain records only through canonical owners.
4. Add additive D1 migrations only when persistence cannot safely reuse existing generic records.
5. Correct all visible/version truth mismatches.
6. Add regression tests that prove actual journeys rather than labels.
7. Update memory/truth documents only after evidence exists.

## Explicitly forbidden

- Recreating `eco-system-db`.
- Force-pushing or rewriting production history.
- Deleting existing migrations or historical records.
- Replacing canonical ledger/stock/membership/loan truth with generic workspace records.
- Marking real Mobile Money/wallet/escrow/provider messaging as production without provider/security qualification.
- Changing `realMoneyEnabled=false` in this closure.
- Treating a UI button or a catalogue entry as sufficient Definition of Done.

## Regression matrix

Must stay green:
- auth/session/tenant isolation;
- several independent tontines and per-share scheduling;
- ledger atomicity/idempotency/reversals;
- member-control reserve workflow;
- savings yield five-policy comparison;
- loans/repayments no unpaid-interest compounding;
- documents/R2;
- forum/realtime;
- marketplace/group shop;
- AdManager privacy;
- PWA/offline/i18n;
- 1.3.4 voice/two-sheet flows;
- BIR+/Cloudflare bindings.

## Deployment gate

Production deployment is permitted only after:
1. full `npm run ci` green on the closure branch;
2. readiness report generated and truthful;
3. all new in-scope operational journeys have tests;
4. BIR+ pre-deploy source + D1 export/restore/integrity/SHA/R2 mirror;
5. additive migrations only;
6. Worker/PWA smoke including version and critical new surfaces;
7. BIR+ post-deploy D1 export/integrity/SHA/R2 mirror.
