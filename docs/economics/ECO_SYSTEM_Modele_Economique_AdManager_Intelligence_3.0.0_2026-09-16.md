# ECO-SYSTEM — Modèle économique, AdManager et Intelligence Commerciale 3.0.0
**Date : 16 septembre 2026**  
**Statut : architecture économique de référence — les montants d'exemple ne sont pas des prévisions.**

---

# 1. Thèse économique

Eco-System doit rester gratuit ou presque gratuit pour le membre ordinaire et pour le cœur de gestion d'une association.

La plateforme est financée par la valeur qu'elle crée autour des groupes :

- visibilité ;
- concentration de la demande ;
- accès fournisseurs ;
- achats groupés ;
- programmes partenaires ;
- programmes ONG ;
- outils professionnels ;
- publicité ;
- intelligence statistique ;
- événements ;
- services documentaires ;
- transactions réellement capturées.

**Formule directrice :**

> Ne pas vendre les personnes. Vendre des services, de l'accès à une demande agrégée et de l'intelligence économique gouvernée.

---

# 2. Réalité camerounaise à intégrer

Le produit doit supposer que :

- de nombreux achats restent négociés ;
- le prix affiché est souvent le début de la discussion ;
- une partie des transactions se conclut physiquement ;
- acheteur et vendeur peuvent avoir intérêt à sortir de la plateforme ;
- Mobile Money est un moyen de paiement important mais ne supprime pas le cash ;
- la connectivité peut être irrégulière.

La réponse n'est pas d'interdire la négociation.

**La négociation doit entrer dans Eco-System.**

---

# 3. Le problème du « vendeur qui ne déclare pas »

Modèle faible :

1. Eco-System envoie un client.
2. Le client arrive chez le vendeur.
3. Ils négocient.
4. Ils paient en espèces.
5. Eco-System demande au vendeur s'il a vendu.
6. Le vendeur répond non.
7. Revenu Eco-System = 0.

Ce rail peut exister, mais il ne doit pas financer l'entreprise.

---

# 4. Matrice anti-fuite

Chaque monétisation est évaluée selon sa dépendance à une déclaration volontaire.

| Rail | Dépend du vendeur après vente ? | Robustesse |
|---|---|---|
| Campagne AdManager prépayée | non | très élevée |
| Sponsoring | non | très élevée |
| Abonnement partenaire | non | élevée |
| Accès fournisseur à appel d'offres | non | élevée |
| Programme ONG/SaaS | non | élevée |
| Insights | non | élevée |
| Réservation d'un Deal | peu | élevée |
| Coupon/QR consommé | peu | élevée |
| Lead vérifié | peu | moyenne/élevée |
| Commission paiement intégré | non si paiement capturé | élevée |
| Commission sur vente cash déclarée | oui | faible |

Objectif : que les rails faibles deviennent minoritaires.

# 6. Eco-System Demand Exchange

## 6.1 Données sources

La demande peut provenir de :

- Tontine en nature ;
- achat groupé ;
- projet ;
- besoin de formation ;
- événement ;
- demande Marketplace ;
- besoin d'assurance/financement.

Exemple :

- ECO-GRP-A1 : 300 savons ;
- ECO-GRP-B2 : 500 savons ;
- ECO-GRP-C3 : 200 savons.

Demande consolidée :

> 1 000 savons, zones Yaoundé, période novembre.

Aucun nom de membre n'est requis.

## 6.2 Pouvoir de négociation

Un fournisseur hésitera à réduire un produit pour un seul client.

Il peut accepter une réduction forte pour :

> 1 000 unités avec demande structurée.

Eco-System transforme donc les données en **pouvoir d'achat collectif**.

# 7. Reverse Auction

Au lieu de demander :

> « Quel fournisseur voulez-vous ? »

Eco-System demande :

> « Qui peut servir 1 000 unités, à quel coût total rendu, dans quel délai et avec quelle fiabilité ? »

Exemple :

| Fournisseur | unité | transport | capacité | délai | fiabilité |
|---|---:|---:|---:|---:|---:|
| A | 900 | 50 000 | 1 000 | 5 j | 98 |
| B | 870 | 150 000 | 1 000 | 12 j | 90 |
| C | 820 | 20 000 | 300 | 3 j | 95 |

C est moins cher mais incapable de livrer le volume.

Le moteur classe le **coût rendu + capacité + fiabilité + délai**.

---

# 8. Deal Lock

Un Deal Eco-System peut porter :

- `dealId` ;
- fournisseur ;
- prix normal ;
- prix Eco-System ;
- quantité ;
- validité ;
- localité ;
- conditions ;
- token/QR ;
- avantages ;
- nombre maximal.

Exemple :

> Prix public : 10 000 F  
> Prix Eco-System : 8 500 F  
> valable 72 h  
> livraison au lieu de réunion  
> litige/proof inclus.

Le client a une raison de rester dans le parcours.

---

# 9. Négociation native

Le prix ne doit pas être figé lorsque le marché négocie.

États :

ASKED → OFFERED → COUNTERED → ACCEPTED / REJECTED / EXPIRED.

Exemple :

vendeur : 150 000  
prix Eco-System : 139 000  
client : 125 000  
vendeur : 130 000  
client accepte.

L'événement est mesurable sans espionnage externe.

---

# 14. AdManager — ciblage

## 14.1 Contextuel

Exemple :

> contenu sur agriculture → campagne d'intrants agricoles.

## 14.2 Intérêts first-party

Exemple :

> utilisateur interagit régulièrement avec achats groupés.

## 14.3 Groupe agrégé

Exemple :

## 14.4 Interdit

Pas de ciblage :

- dette membre ;
- solde ;
- CNI ;
- téléphone ;
- santé ;
- litige ;
- identité brute.

---

# 15. Privacy Budget publicitaire

Proposition :

Chaque critère de ciblage possède un coût de confidentialité.

Plus une audience devient petite/spécifique, plus le moteur refuse ou généralise.

Exemple :

Yaoundé + intérêt savon + association = acceptable si audience suffisante.

Yaoundé + Tontine Savons + 1 seul groupe + faible nombre de membres = refus/généralisation.

---

# 16. Frequency Cap intelligent

Au-delà d'un seuil :

- baisse de rendement ;
- irritation ;
- retours négatifs.

Le moteur doit donc optimiser :

**revenu marginal - coût de fatigue utilisateur.**

Une campagne trop agressive perd progressivement ses impressions.

# 23. CNI et économie

La CNI améliore le rapprochement historique et la confiance.

Elle n'alimente jamais :

- ciblage publicitaire ;
- scoring marketing ;
- enchère publicitaire.

Elle peut servir à :

- preuve d'identité ;
- déduplication ;
- récupération/rapprochement ;
- vérification réglementaire future lorsque nécessaire.

# 31. Limites de coûts actuelles à surveiller

Les limites Cloudflare changent.

À la date du document :

- Workers Free : 100k requêtes/jour ;
- D1 Free : 5M rows read/jour, 100k rows write/jour, 5 GB compte ;
- Analytics Engine Free : 100k datapoints/jour, 10k requêtes lecture/jour ;
- Workers AI : 10k neurons/jour gratuits ;
- R2 : allocation gratuite de stockage et opérations.

Depuis le 1er septembre 2026, le dépassement des limites quotidiennes D1 Free peut bloquer les requêtes jusqu'au reset.

# 34. Règle de protection du gratuit

Avant de rendre payante une fonction de base, demander :

1. génère-t-elle directement un coût important ?
2. l'utilisateur professionnel en tire-t-il un revenu ?
3. existe-t-il un rail B2B qui peut financer cette fonction ?

Priorité :

**faire payer celui qui capture de la valeur économique, pas celui qui essaie seulement de gérer sa tontine.**

# 35. Exemples Eco-System

## Savons

15 groupes totalisent une demande de 4 500 savons.

Eco-System demande des devis.

Fournisseur A propose 900 F, B 830 F pour volume complet.

Eco-System obtient :
- prix utilisateur inférieur ;
- fournisseur gagne volume ;
- Eco-System reçoit forfait accès + commission contractuelle ou sponsoring.

## Épargne

Les masses agrégées montrent un besoin de coffre/produit d'épargne pour plusieurs groupes.

Une institution peut proposer un programme.

Elle reçoit des statistiques agrégées et non la liste des épargnants.

## ONG

Une ONG veut accompagner 100 associations.

Eco-System vend :
- configuration programme ;
- suivi ;
- formation ;
- tableaux agrégés ;
- rapports.

# 36. Règle finale

La donnée doit faire simultanément :

- baisser le coût pour le groupe ;
- augmenter la qualité des services ;
- augmenter le volume du partenaire ;
- augmenter la marge Eco-System.

Si une collecte de données ne sert aucun de ces objectifs clairement définis, elle ne doit probablement pas être collectée.
